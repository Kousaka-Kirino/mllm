# 01 架构说明（一页纸）

> 面向：复试老师 / 面试官 / 一个月后的自己。读完这一页，应该能画出整条数据流。

## 1. 一句话

用 **8GB 笔记本显卡**训一个 **5.89 亿参数**的图表问答模型，然后用 **2×2 受控实验**
回答一个具体问题：**它答错是因为看不见字形（acuity），还是因为不看图（prior）？**

## 2. 模型

```
图 1152² ──resize──▶ 384² ──SigLIP-base-patch16-384(冻结, 93M)──▶ 576×768 patch 特征
                                                                    │
                                                    connector(2.30M, 唯一训的部分)
                                                                    ▼
                                            Qwen2.5-0.5B-Instruct(494M) + LoRA(r=8, 1.08M)
                                                                    ▼
                                                            "A"（≤8 token，带 eos）
```

| 项 | 值 | 来源 |
|---|---|---|
| 总参数 | 589.5M | `python -m stage2_model.smoke --load` |
| 可训练参数 | **3.38M**（connector 2.30M + LoRA 1.08M） | 同上 + `stage3_train/sft.py` |
| 视觉 token | 576（mlp）/ 144（pixelshuffle）/ 64（resampler） | `stage6_ablation` |
| 单图单问延迟 | ~196 ms（前向）/ ~450 ms（含 generate 的端到端） | `outputs/bench`、S2 |
| 峰值显存 | 1.4GB（前向）/ 3.8GB（SFT，batch=1 + 梯度检查点 + bf16） | 实测 |

**为什么要冻 ViT**：8GB 里没有空间给 93M 视觉塔的反向传播 + 优化器状态；
而且本项目的研究对象是"连接器能不能把视觉信息送进语言模型"，不是"ViT 能不能学好"。

## 3. 数据：每条样本都是一个可复算的因果对

- 渲染器 `stage1_data/render.py`：matplotlib，固定 figsize=6in，`dpi=边长/6`，
  三种图（bar / grouped_bar / line），4 种字体缩放，噪声与干扰项可关。
- **acuity 是量出来的**：`measure.py` 按文字 bbox 裁块、阈值化数着墨行高，
  同时记录"原图尺度"和"模型输入尺度"；分箱阈值（6.5 / 4.5 / 3.0 px）是**预注册常量**，
  写进 `data/acuity_thresholds.json` 后冻结，后续 profile 复用，除非显式 `--recalibrate`。
- **先验是操纵出来的**：`conflict.py` 生成"一致/冲突"成对样本——
  position（首末位置）、marginal（yes/no 分布）、numeric（计数爱答 2）、order（问法顺序）。
  同一张图、同一个问题、只改一个因素，金标随之翻转。
- **family 划分**：一个 family = 一张图 + 它的所有问法；成对样本整体进同一个 split，
  避免"同一张图横跨 train/test"这种最隐蔽的泄漏。四个 split：
  train / val / dev_test / locked_test（80/10/5/5）。
- pilot：636 family / 636 图 / 30MB；ρ（先验强度）实测 0.7406。

## 4. 训练：两段，各自只训一个东西

| 阶段 | 训什么 | 冻结什么 | 结果 |
|---|---|---|---|
| `stage3_train.align` | connector | ViT + LLM | 60 步，loss 6.37 → 0.61，45s，3.5GB |
| `stage3_train.sft` | connector + LoRA | ViT | 237 步，loss → 0.45，~4min，3.8GB |

`check_loss_mask.py` 的 9 条不变量是这段的护栏：视觉 token 与 prompt 必须 -100，
只有答案位参与 loss；改 prompt 的 token 不能改变 loss，改答案必须改变 loss。

## 5. 评测：四个条件 × 四格

`stage4_eval` 对同一条样本跑四种条件：`correct_image` / `mismatched_image`（同一数据集里
另一张图）/ `prior_only`（灰图）/ `image_only`（只给图）。四格 = acuity(easy/hard) × prior(一致/冲突)。

统计：
- 比例给 **Wilson CI**；
- 两模型比同一批题给 **McNemar 精确检验** + 胜/负/平；
- 效应量的 CI 用 **按 family 整簇 bootstrap**（同图多题相关，不能独立重采样）。

## 6. 三个"看起来能修，其实修不动"的负结果

1. **换图不掉点**：correct_image 0.512 vs mismatched_image 0.512，80 对里各只有 1 对翻转
   （McNemar p = 1.0）→ 主导信号是先验。
2. **放大不提升**：salient 0.542 vs full 0.583（−0.042，不显著）→ acuity 不是当前瓶颈。
3. **GRPO 组内无信号**：12 条 rollout 里 5/6 组奖励全同 → 优势恒为 0，等于没梯度。

这三条决定了这个项目的诚实结论是"**小模型的图表失败主要是 prior 问题，不是分辨率问题**"，
而不是"我训了一个更强的图表模型"。
