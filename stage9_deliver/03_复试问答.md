# 03 复试问答（按被问到的概率排序）

> 每题给"短答（30 秒）"和"如果继续追问"。
> 所有数字都能在 `reports/REPORT_2.0.md` 与 `outputs/` 里查到。

## Q1 你这个项目和 mini-GPT4 / LLaVA 有什么区别？

**短答**：LLaVA 类工作是"用更多数据训一个更强的模型"；我做的是"用受控实验回答一个机制问题"。
我把 acuity（看不看得见）和 prior（看不看图）做成两个**可独立操纵**的变量，
用 2×2 设计拆开，因此能给出"失败原因"而不只是"准确率"。

**追问**：那你的结论能推广吗？——不能推广到"所有 mLLM"，但能推广到"图表这类
结构化、答案空间小、先验极强的场景"。这正是它值得单独研究的原因。

## Q2 为什么只训 connector 和 LoRA，不训 ViT？

**短答**：8GB 显存下，93M 视觉塔的反向传播 + Adam 状态大约要 1.2GB，加上激活就超了；
更重要的是我的研究对象是"视觉信息有没有被送进语言模型"，不是"ViT 能不能学好"。
冻住 ViT 反而是**控制变量**：所有模型共享同一个视觉前端，差异只能来自连接器和语言侧。

**追问**：那如果 ViT 本身就看不清小字呢？——我用 S7 的放大实验验证过：
把金标区域裁出来放大 3 倍，准确率 0.542 vs 全图 0.583，**没有提升**。
这说明瓶颈不在"像素够不够"，而在"模型用不用"。

## Q3 acuity 为什么是"量出来"的，而不是按字号分档？

**短答**：因为我一开始就是按字号分档的，然后发现**同一字号在不同图里着墨高度差 30%**
（数字 1 比 8 窄、中文标签比英文高）。所以改用：渲染后按文字 bbox 裁块、阈值化数着墨行高，
记录模型输入侧的像素值，再按**预注册的绝对阈值**分箱（6.5 / 4.5 / 3.0 px）。

**追问**：预注册怎么保证不是事后挑的？——阈值写在 `data/acuity_thresholds.json` 里，
带 `rule` 和 `source` 字段，`validate.py` 会检查它和当前数据一致；重算必须显式 `--recalibrate`。

## Q4 "换图不掉点"会不会是因为两张图太像？

**短答**：错配图是从**同数据集**里随机抽的另一张图（同样式、同尺寸、不同数据），
所以"看不懂"不成立；而模型对它的答案与正确图**逐格相同**。
更强的证据是 `prior_only`（灰图）条件：四格掉到 0.25/0.10/0.20/0.00——
说明它确实在从图里取信息，只是这点信息不足以覆盖先验。

**追问**：会不会是 token 太多、注意力被稀释？——这是 S6 的动机（iso-token 对比），
三个连接器 576/144/64 token 的显存与延迟都测了，但没有观察到"token 少反而更准"。

## Q5 GRPO 为什么没work？你怎么确定不是实现错了？

**短答**：不是实现错，是**组内没有方差**：G=2–4 时，同一道题采 2–4 个答案，
经常全对或全错（这题太难/太简单），优势 = (r−mean)/std 恒为 0。
我统计了 `zero_adv_groups = 5/6`，并保留了 RFT 对照（拒绝采样 + SFT），
结论是"这个规模下 PPO 风格更新退化成加权 SFT"。

**追问**：那 GRPO 什么时候有用？——需要"同题多解、且对错混杂"的分布，
即中等难度 + 足够大的 G。8GB 上 G 只能到 2–4，且模型已经把简单题做对、难题全错，
正好落在最没有梯度的区间。这是**资源约束下的负结果**，我把它写进了报告而不是藏起来。

## Q6 你的统计为什么这么麻烦（Wilson / McNemar / 聚类 bootstrap）？

**短答**：因为样本小。80 条样本上 0.95 与 0.90 的 Wilson 区间是重叠的，
直接说"提升了 5 个点"是错的；同一张图的多个问题又高度相关，
独立重采样会低估方差，所以要按 family 整簇重采样。

**追问**：McNemar 和 bootstrap 分别用在哪？——McNemar 用于"两个模型在同一批题上"的
配对比较（只看不一致的题）；bootstrap 用于效应量的区间（prior_effect 的 CI）。

## Q7 如果给你更多显存/时间，你下一步做什么？

三件事，按性价比排序：
1. 把 pilot 换成 full（≥200 family/格），把 CI 收窄到 ±0.05 以内；
2. 先验去偏：在训练集里做 prior 平衡 + 反事实增广，看冲突格能不能从 0 抬起来；
3. 连接器换成 resampler（64 token）后重训，验证"更少 token 是否抑制先验捷径"。

## Q8 这个项目里你踩过的最大的坑？

**短答**：SFT 第一版模型答完不停、格式分恒为 0。查了两小时才发现答案后面没接 eos，
模型把 `Answer:` 后面当成了自由续写。修完 loss 从 10.3 掉到 0.45。
第二个坑是"loss 没 mask prompt"——loss 看着在降，其实模型在背问题。
这两个坑后来都写成了不变量检查（`check_loss_mask.py` 的 9 条断言）。
