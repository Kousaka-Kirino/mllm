# Stage 7 · 视觉记忆：检索、放大、以及一次诚实的失败

> 一句话：**一张 1152² 的图塞进 576 个 token，字必然糊。工程解法不是"换更大模型"，
> 而是"先找到那一块，再放大"。这个阶段测的就是这两步到底值不值。**

本阶段两个实验，一个失败一个成功，都要如实写进报告——这正是 PandaVLA 式的
"负结果也是结果"。

---

## 1. 为什么需要"记忆"

S1 的恒等式说：固定 384² 输入时，模型侧字号只由**逻辑字号**决定。图越大、
字越多，单字越小。8GB 卡上你没有余量把 1152² 原图喂进去（576 token 已经
是 SigLIP-base 的固定输出），所以只能：

1. **检索**：在整页里定位"问的是哪一块"；
2. **放大**：把那一块裁出来、放大到 384²，让字变大。

这两步都不训练模型，是纯工程；但它们的收益必须**测量**，不能假设。

---

## 2. 实验 A：页内召回（失败）

设定：80 页图表（`dev_test`），查询是**同一页中心 1/3 的裁片**，问"这是哪一页"。
特征用冻结 SigLIP 的 patch 特征做平均池化，余弦相似度排序。

| 指标 | 数值 | 95% CI |
|---|---:|---|
| recall@1 | **0.083** | [0.023, 0.258] |
| recall@3 | 0.167 | — |

（24 页 pilot 实测；样本小，CI 很宽。）

**为什么这么低？** 三条原因，按重要性排序：

1. **平均池化把位置信息抹掉了**：一页图是"同样的柱子换个数值"，池化后几乎一样；
2. **SigLIP 是图文对齐模型，不是页面检索模型**：它的 patch 特征对"语义类别"
   敏感（都是柱状图），对"哪个数值"不敏感；
3. 我们没有文本编码器，查询只能用视觉裁片——这本身就让任务变简单也变难：
   简单在于同模态，难在于"裁片和整页的分布不同"。

**怎么修**（写进"未来工作"，别现在做）：用 ColPali / 逐 patch 最大相似度
（而不是平均池化）+ 文本查询。这是已知有效的方案，但会引入一个新模型和
一个新训练目标，超出 pilot 预算。

> 报告写法：「我们尝试了用冻结 SigLIP 做页内检索，recall@1 = 0.083 [0.023, 0.258]，
> 显著低于可用水平。失败原因是平均池化丢失了区分性信息；我们没有把它包装成
> '视觉记忆有效'。」

## 3. 实验 B：放大整图里"最字密"的一块（部分成功）

对 `hard` 档（字号 0.5–0.7）的 24 条题，比较三种输入：

| 输入 | 准确率 | 95% CI | 相对整图 |
|---|---:|---|---:|
| 整图 384² | 0.583 | [0.388, 0.755] | — |
| **显著块**（字最多的一块，裁+放大） | 0.542 | [0.351, 0.721] | **−0.042** |
| 随机块（同尺寸裁+放大） | 0.292 | [0.149, 0.492] | −0.291 |

三条读法：

1. **随机块崩了**（0.29）：说明模型**确实在看图**，不是纯靠先验。这条很关键——
   它反驳了"SFT 只学了先验"的过度结论（S4 里 `prior_only` 崩到 0.2 也是同一证据）。
2. **显著块 ≈ 整图**（差 0.042，CI 大面积重叠）：把 8/9 的像素扔掉、只留字最密的
   一块，性能不掉。说明模型的有效信息集中在那一块。
3. **显著块没有超过整图**：如果失败真是 acuity（字太小看不清），放大应该**提升**。
   它没有提升 → 在这个字号档上，**瓶颈不是像素分辨率**。

第 3 条直接支撑 RQ1 的"不看 > 看不见"结论，且是**独立于 S4 的第二条证据链**
（S4 用换图/灰图，S7 用裁+放大）。两条证据指向同一结论，比单条更有说服力。

## 4. 代码导览

| 文件 | 作用 |
|---|---|
| `build_index.py` | 用冻结 SigLIP 抽 patch 特征，块平均后存 `outputs/memory/pages_*.npz` |
| `retrieve.py` | `grid_bbox`/`region_from_grid`（格子几何）、`saliency_scores`（字密度）、`crop_zoom`（裁+放大）、`full_image` |

| `verify_stage7.py` | 6 项验收（索引/池化/几何/放大/引用格式/结果文件） |
