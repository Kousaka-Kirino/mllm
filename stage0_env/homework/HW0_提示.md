## 作业 1：显存账

一个够用的估算式：

```
权重   = (93M + 494M + 4M + 12M) × 2 B ≈ 1.2 GiB
激活   ≈ batch × seq × hidden × 层数 × 2 B × k
         seq = 576(视觉) + 32(文本) = 608，hidden = 896，层数 = 24
         开梯度检查点：k ≈ 0.3（只存层输入）；不开：k ≈ 1.0
logits ≈ batch × seq × vocab × 2 B      ← vocab 151936，这一项很大
```

代入 batch=1、开检查点：

```
激活   ≈ 1 × 608 × 896 × 24 × 2 × 0.3 ≈ 7.9 MB   → 可忽略
logits ≈ 1 × 608 × 151936 × 2         ≈ 176 MB   → 主要临时区
峰值   ≈ 1230 + 176 + 碎片 ≈ 1.5–2.2 GiB
```

**验收标准**：估算与实测差 < 60%（`hw1` 的返回值 0），并且能在结论里指出
"差在 logits 还是碎片"。差 2 倍也不丢人，说不清差在哪才丢人。

## 作业 2：真实训练预算

**验收标准**：三次采样中位数 ≥ 7000 MiB → `预算充足`；
5000–7000 → `预算偏紧，batch=1 + 梯度累积`；< 5000 → `先关程序`。
结论里必须同时出现**中位数**和**极差**（极差大说明有后台进程在波动）。

参考结论：`中位数 7091 MiB，极差 12 MiB，预算充足，可 batch=2`。

## 作业 3：门槛值

**验收标准**：交一段文字，至少回答：

1. `min_free_mib_for_train` 你填多少？为什么（要留出 checkpoint/评测的余量）？
2. `min_free_gb` 你填多少？依据是"权重 1.2GB + 数据 X GB + checkpoint Y GB"里的哪一项？
3. 哪一项你**故意**放宽了，放宽的代价是什么？

一个好答案长这样：
> `min_free_mib_for_train=5000`：SFT 峰值约 4.3GB，留 0.7GB 给评测时的 batch 抖动；
> `min_free_gb=12`：数据 5GB + 权重缓存 2GB + 4 个 checkpoint × 1.3GB ≈ 12GB；
> 放宽了 `name_contains`（允许 4050 6GB 跑 pilot），代价是主实验必须换机器。

## 常见错误

- 拿 `total` 当可用显存 → 高估 1–2GB；
- 用 HEAD 探网络 → 某些镜像站直接 405；
- 忘记 `logits` 临时区 → 估算偏低一半以上；
- 只测一次 → 冷启动把 load 时间拉高 3 倍，误判"显卡不行"。
